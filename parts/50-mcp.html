MCP «Сбережения»

Один протокол для своего помощника и для чужого агента

Помощник банка сам работает через этот MCP с первого этапа. На четвёртом этапе тот же сервер открывается внешним агентам клиента: любой MCP-клиент, своя LLM, семейный советник. Что бы ни пришло снаружи, исполнение одно: подтверждение в Сбербанк Онлайн. Как клиент подключает свою LLM, показано в прототипе, путь «Своя LLM через MCP».

Ресурсы

Каталог продуктов и ставок · условия и надбавки · политика клиента · цели и автонакопления · журнал действий. Только данные самого клиента, без ПДн третьих лиц.

Промпты

«Подбери вклад под запрос» · «Что сделать с вкладом при закрытии» · «Разбери остатки на счетах» · «Объясни проще». Готовые шаблоны, чтобы внешний агент вёл себя как наш помощник.

Скоупы

read смотреть · propose получать расчёты и предложения · execute исполнять с подтверждением в приложении. Автопилот без подтверждения внешним агентам недоступен.

Безопасность

OAuth, токен на 14 дней, отзыв в один тап, лимиты сумм и частоты, цифры только из систем банка, каждый запрос в журнале с идентификатором агента.

Как харнес ведёт запрос агента

Выберите запрос. Трассировка показывает проверки харнеса, а телефон справа: что видит клиент. Исполнение ждёт подтверждения на телефоне, нажмите «Подтвердить».

Рынок уже пробует открытые агентские доступы: Danske Bank пилотирует MCP для корпоративных клиентов только на чтение, Т-Банк дал инвесторам подключать агентов вплоть до сделок с подтверждением в сессии. Для вкладов и счетов массового клиента такого продукта пока нет.

Харнес

Что вокруг модели, чтобы помощник пережил прод

Харнес по вкладам и счетам: политики, ограждения, проверки и журнал, в которые завёрнута любая модель, своя или внешняя. Модель заменяема, харнес и доверие клиента нет.

Политики и лимиты

Уровень автономии L0–L3, скоупы агентов, лимиты сумм и частоты, резерв, список «не трогать», минимальная выгода. Политика одна для своего помощника и внешних агентов.

Ограждения

Факты только из инструментов: ставки, остатки, даты. Запрет советов вне периметра сбережений. Описания операций и тексты агентов считаются данными, не инструкциями.

Evals как критерий релиза

Золотые сценарии по сегментам, регресс при смене модели или промпта, метрика галлюцинаций в цифрах, проверка тона для «Осторожного». Релиз не выходит без прохождения.

Наблюдаемость и аудит

Журнал каждого предложения и действия с источником, объяснением и версией модели. Доступен клиенту, комплаенсу и разбору инцидентов.

Маршрутизация моделей

GigaChat по умолчанию, малые модели для классификации и маршрутизации, кэш типовых ответов. Замена модели не меняет продукт. Своя LLM клиента подключается через MCP.

Человек в контуре

Передача оператору с контекстом и расчётом, стоп-кран на уровне клиента и сегмента, откат отложенных действий, доверенное лицо для осторожных.

Харнес принадлежит продукту вкладов и счетов, а не ML-платформе: ограничения формулирует владелец продукта вместе с риском и комплаенсом, evals пишут продуктовые команды, модель выбирает платформа.
